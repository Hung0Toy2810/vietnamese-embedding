# Semantic Document RAG

A local, source-grounded document workspace. The package name is historical; ingestion and answering are document-agnostic.

## Semantic graph, not a formatting graph

1. Docling extracts ordered text, tables and source locations from supported document formats. PDF typography and page boundaries are not graph features.
2. Text is mapped to whitespace-canonicalized language units with exact original source offsets. Sentence punctuation helps form small units; oversized sentences are split without losing source text.
3. The packaged encoder embeds each unit. Bounded nearest-neighbor searches propose candidate pairs anywhere in the document. Shortlisting preserves two candidate opportunities per unit so a lower-scoring topic is not excluded by a global threshold.
4. Qwen inspects semantically diverse examples and produces a validated `ChunkPlan` with a document-specific shortlist quantile and parent/child token budgets.
5. In overlapping, token-bounded language windows, Qwen identifies distinct subjects, then assigns each unit to a subject or marks it unresolved/metadata. Continuations, conditions and outcomes remain with the object they describe. Reviewed overlap assignments carry into the next window. Short local IDs are checked against actual source units; endpoint text is copied by code, not regenerated by the model.
6. NetworkX groups the subject-to-member edges into connected components. A second pass asks for explicit true/false decisions on distant embedding candidates. Only positive decisions create navigation links; omitted decisions create no edge and are recorded as unreviewed. These links never merge different subject groups. Sequence edges are excluded from semantic grouping. Isolated units are preserved, and large groups are divided within the parent budget. Semantic links remain navigable across parents.
7. Child chunks fit the real encoder tokenizer, including its special tokens. Every source unit and non-whitespace character must remain covered.

A semantic relation is an LLM hypothesis with validated source IDs. Its endpoint text comes from the original source, but that does **not** prove the relationship or answer is correct. In particular, relation labels and subject assignments require quality review. The graph is neither a legal authority nor a guaranteed complete knowledge graph.

## Run

From the repository root, after restoring the encoder artifacts:

```bash
python -m pip install -r requirements.txt -r legal_rag/requirements.txt
ollama pull qwen3.5:9b
python -m legal_rag.webapp
```

Open http://127.0.0.1:8765. The server binds to localhost. It is a local workspace, not an authenticated multi-user deployment.

CLI ingestion and querying:

```bash
python -m legal_rag.build /path/to/document.pdf
python -m legal_rag.ask DOCUMENT_ID "What conditions and exceptions apply?"
python -m legal_rag.ask DOCUMENT_ID "return policy" --search-only
```

`build` prints the document ID and version. To download the optional law sample without any custom text repairs:

```bash
python -m legal_rag.download
python -m legal_rag.build legal_rag/data/sample.pdf
```

The old 408-article parser and its fixed Gazette-page substitution are not used. Existing old PDF/index files are retained locally but are not silently migrated into an active semantic index. Re-upload originals to analyze them with the new pipeline.

## Supported input

PDF, DOCX, PPTX, XLSX, HTML, Markdown and UTF-8 TXT. Native formats and text PDFs have small format-conversion checks; complex documents still require review. Docling handles OCR when supported by its installed backend. OCR quality and language coverage depend on the installed models. Missing text, poor conversion confidence and parser errors must be reviewed rather than called fully successful extraction.

Defaults: 25 MB/upload, 600 pages/document, 2,000,000 extracted characters. Format support does not establish multilingual retrieval quality; the encoder was trained for Vietnamese.

PDF files retain their original viewer. Other formats receive an inert extracted-text preview and retain the downloadable original. Uploaded HTML is never rendered as active application HTML.

## Storage and execution

`data/workspace/catalog.sqlite` stores documents and jobs. Each document has immutable source bytes, model-call caches and independent version folders containing:

- `manifest.json`: implementation/configuration and model fingerprints;
- `parsed.json`, `atoms.json`, `units.pt`: extracted content, mapped language units and embeddings;
- `plan.json`, `pairs.json`, `graph.json`: selected policy, candidate pairs and source-linked semantic hypotheses;
- `index.json`, `indexed.json`, `preview.html`: chunks, indexing completion and inert preview.

LangGraph orchestrates the ingestion stages. Completed artifacts and validated model calls are reused when interrupted jobs restart with unchanged configuration. Graph prompts use short local IDs. Echoed context anchors are validated and omitted from new assignments; the literal string "null" is normalized to JSON null. Unknown IDs, missing units and conflicting overlap scopes still fail validation. Retries use the same version-specific vector IDs. The active version changes only after indexing completes. Warnings leave a pending version requiring explicit acknowledgement; the previous active version remains available.

A sequential worker limits concurrent model memory. Large intermediate tensors stay on disk between stages. Qdrant local storage is used for development; its single-process limitations apply. Files hidden by the delete endpoint remain on disk for audit/recovery; deletion is not secure erasure or immediate storage reclamation.

## Retrieval and answering

Dense retrieval with the 77M encoder and lexical BM25 are combined by reciprocal-rank fusion. Up to 100 distinct child candidates are reranked by `BAAI/bge-reranker-v2-m3`, retaining up to 10. Version/document filters apply to vector search. Long questions are windowed for encoder retrieval; the reranker rejects oversized pairs rather than silently truncating them.

Semantic parents and source-ID-validated one-hop graph neighbors propose source context. A short native JSON selection step chooses relevant subject groups before full passages are read; it can keep multiple groups for comparisons or dependencies. This reduces cross-subject noise but is not a guarantee of perfect relevance. Selected passages are bounded by UTF-8 bytes and the pinned Qwen generator tokenizer; additional headers are counted by the input guard. Ranking chooses passages, then their original reading order is restored. Up to 1 KB is reserved for boundary context. If a fact remains unsupported, the writer gets one retry with preceding original units as numbered evidence, within the same byte budget. Adjacency adds reading context, never a semantic grouping edge. A middleware checks messages and tool schemas before each inference turn and reserves generation/chat-template headroom. These are conservative input estimates, not exact Ollama template counts; deployment still needs profiling. Oversized parents expose remaining text-unit IDs so the agent can inspect further passages instead of silently treating a partial parent as complete.

Agent tools:

| Tool | Purpose |
|---|---|
| `search_documents` | Hybrid retrieval and reranking in the selected document/version |
| `read_section` | Read a semantic parent or individual source-unit ID |
| `explore_related` | Inspect relation hypotheses and their source-unit IDs |
| `create_mindmap` | Visualize actual stored relationships behind sources read this turn |
| `search_web`, `read_web` | Optional discovery/read of allowed public HTTPS HTML sources |

Source text cannot authorize tool calls or change system instructions. External search is off by default. Enabling it sends queries externally. Allowed domains are configurable; redirects/private network destinations are rejected. Web freshness and legal applicability are not automatically verified.

Qwen3.5:9B runs through Ollama, streaming until completion, with no inference read timeout and `num_predict=-1`. Ingestion keeps its evaluated extraction profile. Answer generation uses the [Qwen3.5-9B recommended non-thinking sampling profile](https://huggingface.co/Qwen/Qwen3.5-9B#best-practices): temperature 0.7, top-p 0.8 and presence penalty 1.5, with seed 42. Reasoning is optional (`RAG_ANSWER_THINKING=true`); ingestion uses non-thinking structured extraction by default (`RAG_INGESTION_THINKING=true` enables reasoning for that stage). Completed-turn limits bound the agent loop; they do not stop an in-progress inference. Exhausted turn or context budgets produce an explicit processing/validation failure with a recorded completion reason. This is distinguished from finding no supporting evidence in the document.

The LangChain agent collects source context through tools. Its draft is not shown as an answer. A separate native Ollama JSON-schema call using the same model writes the final response from the original numbered passages. This avoids relying on complex nested final-tool arguments. `FinalAnswer` contains factual claims, each with source/passage references, plus requested/unsupported information needs and follow-up questions. The executor validates reference bounds, attaches `[Source n]` tags to each claim and copies the original passages into the evidence payload. The model does not have to reproduce long quotations or manually format citations. Generated paragraphs, labels, lists and reference numbers have schema bounds. Missing references and unsupported requested parts are rejected before an answer is displayed. This preserves a clear connection between each claim and its selected evidence, but does not establish logical entailment or completeness. Those still require answer-quality evaluation.

## Configuration

Settings have validated `RAG_` environment overrides. Examples:

```bash
RAG_DEVICE=mps python -m legal_rag.webapp
RAG_ROOT=/path/to/workspace python -m legal_rag.webapp
RAG_PARSER=plain python -m legal_rag.build /path/to/text.pdf
```

`plain` is an explicit text-only diagnostic backend for PDF/TXT/Markdown. It has no OCR or layout analysis and is not advertised as the general parser.

Important settings: `RAG_MODEL`, `RAG_OLLAMA_HOST`, `RAG_ATOM_TOKENS`, `RAG_CANDIDATE_NEIGHBORS`, `RAG_GRAPH_WINDOW_TOKENS`, `RAG_RELATION_BATCH_SIZE`, `RAG_INGESTION_THINKING`, `RAG_ANSWER_THINKING`, `RAG_SOURCE_BYTES`, `RAG_MODEL_ROUNDS`, `RAG_GENERATOR_TOKENIZER`, `RAG_GENERATOR_TOKENIZER_REVISION`, `RAG_WEB_DOMAINS` (comma-separated).

The planner cannot disable relation verification or exceed schema token bounds. Planning and edge verification run during ingestion, not anew for each question. This can be slow on a local 9B model; resumability avoids discarding completed work.

All authored code, comments, prompts and Markdown are English. Vietnamese source data and localization live as data. Historical original reports remain byte-preserved text records.

## Validation and deployment boundaries

Tests cover semantic versus physical proximity, line-wrap invariance, distant dependencies, source coverage, malformed graph relations, strict citations, complete streams, real framework tool loops, version isolation, interrupted ingestion, warning review and durable jobs.

```bash
python -m unittest discover -s legal_rag/tests -v
python -m pyright
```

See [the graph and answer evaluation](../reports/graph-quality-20261022.md) and [the earlier implementation checks](../reports/semantic-rag-20261022.md) for actual live checks and known gaps. Small smoke tests are not a benchmark or proof of enterprise readiness. Authentication, tenant permissions, retention enforcement, distributed workers, server-mode vector deployment, operational backups and a held-out domain QA benchmark must be implemented and validated before exposing this local workspace as a shared enterprise service.
